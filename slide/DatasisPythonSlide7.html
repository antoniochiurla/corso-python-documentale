Chiudere il Cerchio: L'Integrazione Cloud

Il lavoro non finisce quando i dati sono pronti, ma quando sono dove l'azienda li aspetta.
I tre target principali per l'output sono:

  1. SharePoint / OneDrive: Per l'archiviazione dei documenti processati e dei report.
  2. Software via API: Per l'invio diretto dei dati estratti.
  3. Log di Sistema: Per monitorare quali documenti sono falliti e perché.

Integrazione SharePoint

Useremo la libreria Office365-REST-Python-Client. 

pip install Office365-REST-Python-Client

È necessario avere le credenziali (Sito, Client ID e Secret, oppure User/Pass). 

from office365.sharepoint.client_context import ClientContext
from office365.runtime.auth.user_credential import UserCredential

ctx = ClientContext(
      "https://tuo_dominio.sharepoint.com/sites/NomeSito")
      .with_credentials(UserCredential("utente@dominio.it",
                          "password"))

Invio Dati via API REST

Il software aziendale solitamente accetta dati tramite una chiamata POST con un payload JSON. 

import requests

def invia_dati_via_rest(dati_json, api_key):
    url = "https://api.servizio.it/v1/import" # URL ipotetico
    headers = {"Authorization": f"Bearer {api_key}",
               "Content-Type": "application/json"}
    response = requests.post(url, json=dati_json, headers=headers)
    if response.status_code == 200:
        print("Dati inviati con successo al servizio")
    else:
        print(f"Errore invio: {response.status_code}")

Logging: Monitorare il Flusso

In un'automazione remota, non possiamo guardare lo schermo. Serve un file di log che registri tutto quello che succede.
Il modulo logging di Python è lo standard: 

import logging

logging.basicConfig(
    filename='automazione.log',
    level=logging.INFO,
    format='%(asctime)s - %(levelname)s - %(message)s'
)

logging.info(f"Inizio elaborazione cartella {dir}")
logging.error(f"Fallita lettura doc. {doc}: qualità insufficiente")

Logging: I 5 Livelli di Severità

Non tutti i log hanno la stessa importanza. Usare il livello corretto permette di filtrare le informazioni in fase di analisi.

  • DEBUG (10): Informazioni dettagliate, utili solo per diagnosticare problemi (es. "Variabile x vale 10").
  • INFO (20): Conferma che tutto stia procedendo come previsto (es. "Documento processato correttamente").
  • WARNING (30): Indicazione di qualcosa di inaspettato, ma il programma continua a girare (es. "Spazio disco quasi esaurito").
  • ERROR (40): Un problema serio che ha impedito l'esecuzione di una funzione (es. "Impossibile connettersi all'API").
  • CRITICAL (50): Errore fatale, il programma non può più proseguire (es. "Database non trovato").

Personalizzare il Formato (Formatter)

Un log senza timestamp o senza sapere "chi" lo ha generato è poco utile. Possiamo personalizzare l'output usando dei segnaposto.

Segnaposto comuni:

  • %(asctime)s: Data e ora dell'evento.
  • %(levelname)s: Il livello del log (INFO, ERROR, ecc.).
  • %(message)s: Il messaggio testuale che inviamo.
  • %(name)s: Il nome del logger che ha generato l'evento.
  • %(lineno)d: Il numero della riga di codice.

Formatter - Esempio

# Configurazione con formato professionale
logging.basicConfig(
    level=logging.INFO,
    format='%(asctime)s - %(name)s - %(levelname)s - %(message)s'
)
logging.info("Messaggio formattato correttamente")

Logger Modulari: getLogger(name)

In un progetto complesso con più file, non vogliamo usare il "Root Logger" globale. Usiamo invece logger specifici per ogni modulo.

  • Identità: Usando logging.getLogger(__name__) in ogni file, il log indicherà esattamente da quale modulo proviene l'errore.
  • Gerarchia: I log "figli" ereditano le impostazioni dal genitore (Root), ma possono essere spenti o filtrati singolarmente.

Logger Modulari - Esempio

# In ocr_engine.py
logger = logging.getLogger(__name__)

def estrai():
    logger.info("Avvio motore OCR") 
    # L'output mostrerà: ... - ocr_engine - INFO - Avvio motore OCR

Handler: Destinazioni Multiple

Un Logger può inviare i dati a più destinazioni contemporaneamente (es. Console e File) usando gli Handler.

  • StreamHandler: Invia i log alla console (standard output).
  • FileHandler: Scrive i log in un file fisico.

Destinazioni multiple - Definizione

logger = logging.getLogger("AppDocumenti")
logger.setLevel(logging.DEBUG)

# 1. Handler per il File (Logga tutto dal livello DEBUG in su)
fh = logging.FileHandler('full_debug.log')
fh.setLevel(logging.DEBUG)

# 2. Handler per la Console (Mostra solo gli ERRORI per non disturbare l'utente)
ch = logging.StreamHandler()
ch.setLevel(logging.ERROR)

Destinazioni multiple - Utilizzo

# Aggiunta degli handler al logger
logger.addHandler(fh)
logger.addHandler(ch)

logger.error("Questo appare sia in console che nel file!")
logger.debug("Questo appare SOLO nel file log.")

Security: Gestione delle Credenziali

MAI scrivere password o API Key direttamente nel codice.
Useremo un file .env e la libreria python-dotenv per caricare le variabili d'ambiente.

Dotenv

  1. Crea un file chiamato .env:
SP_USER=mario@azienda.it
SP_PASS=MiaPasswordSicura
OPENAI_KEY=sk-xxxx
  1. Caricalo nel tuo script:
from dotenv import load_dotenv
import os

load_dotenv()
api_key = os.getenv("OPENAI_KEY")
