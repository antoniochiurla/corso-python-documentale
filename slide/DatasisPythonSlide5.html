Multi-threading in Python

Eseguire compiti in background

  • Cos'è un Thread? È il "filo" di esecuzione di un programma. Uno script standard ha un solo thread (Main Thread).
  • Perché usarli? Permettono di eseguire compiti senza bloccare il flusso principale.
  • Esempio Document Automation: Mentre il programma scarica 50 PDF da un server lento, il Main Thread può mostrare una barra di avanzamento o permettere all'utente di annullare l'operazione.
  • Memoria Condivisa: Tutti i thread dello stesso programma vedono le stesse variabili (attenzione ai conflitti!).

Implementazione: Il modulo threading

In Python usiamo il modulo threading per creare e gestire questi flussi. 

import threading
import time

def compito_lungo(nome):
    print(f"Thread {nome}: inizio download...")
    time.sleep(2) # Simula attesa di rete
    print(f"Thread {nome}: completato!")

# Creazione del thread
t1 = threading.Thread(target=compito_lungo, args=("Worker-1",))

t1.start() # Avvia il thread (non blocca il codice successivo)
print("Il Main Thread continua a lavorare...")

t1.join()  # Opzionale: aspetta che t1 finisca prima di proseguire
print("Fine programma.")

Il threading è perfetto per operazioni di I/O (Input/Output), dove il processore sta fermo ad aspettare dati esterni.

Limiti dei Thread: Il GIL e la Memoria

Nonostante siano utili, i thread in Python hanno dei limiti importanti:

  1. Il GIL (Global Interpreter Lock): Python permette a un solo thread alla volta di eseguire codice Python "puro". Questo significa che i thread non velocizzano i calcoli matematici pesanti (CPU-bound), ma solo le attese (I/O-bound).
  2. Consumo Risorse: Ogni thread occupa memoria del sistema operativo (circa 8MB di stack). Creare 10.000 thread farebbe crashare il sistema.
  3. Race Conditions: Se due thread provano a modificare la stessa variabile contemporaneamente (es. un contatore), il risultato può essere imprevedibile.

Verso l'Asincronia: Per gestire migliaia di connessioni web (API) in modo ancora più efficiente e leggero, passeremo al modello Async/Await.

Programmazione Asincrona per le API

Velocizzare i flussi di automazione con Async e Await

  • Il Problema: Negli script sincroni (standard), quando invii una richiesta a un'API (es. OpenAI o SharePoint), Python si ferma e "aspetta" la risposta. Se hai 100 documenti, aspetti 100 volte.
  • La Soluzione: La programmazione asincrona permette a Python di fare altro (es. preparare il prossimo documento) mentre aspetta che l'API risponda.
  • Vantaggio: Riduzione drastica dei tempi di esecuzione per compiti "I/O bound" (operazioni di rete).

Parole Chiave: async def e await

Per rendere una funzione asincrona, cambiamo il modo in cui la definiamo e la chiamiamo.

  • async def: Definisce una "coroutine" (una funzione che può essere messa in pausa).
  • await: Dice a Python: "Metti in pausa questa funzione qui, attendi il risultato, ma nel frattempo lascia che l'Event Loop faccia girare altro".
import asyncio

async def saluta():
    print("Inizio attesa...")
    await asyncio.sleep(1) # Simula un'attesa di rete
    print("...Risposta ricevuta!")

# Per farla girare:
# asyncio.run(saluta())

Il Cuore del Sistema: L'Event Loop

Immagina l'Event Loop come un vigile urbano che gestisce il traffico di funzioni.

  1. Python non esegue le coroutine direttamente; le "prenota" nell'Event Loop.
  2. Quando una funzione incontra un await, il vigile la sposta in una corsia di sosta.
  3. Il vigile fa passare la prossima funzione pronta.
  4. Appena l'operazione di rete termina, la funzione originale torna in corsia e finisce il lavoro.

Regola d'oro: In uno script asincrono, tutto ciò che blocca (come time.sleep() o operazioni su file pesanti) deve essere sostituito con versioni asincrone, altrimenti il traffico si ferma per tutti.

Richieste Web Asincrone: aiohttp

La libreria requests è sincrona (blocca il traffico). Per le API usiamo aiohttp. 

import aiohttp
import asyncio

async def chiama_api(url):
    # Gestione della sessione asincrona
    async with aiohttp.ClientSession() as session:
        async with session.get(url) as response:
            status = response.status
            dati = await response.json()
            return dati

Concorrenza: Eseguire più richieste insieme

Il vero potere di async emerge quando vogliamo chiamare l'API per 10 documenti contemporaneamente. Usiamo asyncio.gather. 

async def processa_multipli(lista_url):
    async with aiohttp.ClientSession() as session:
        tasks = []
        for url in lista_url:
            # Creiamo una lista di "compiti" da fare
            tasks.append(session.get(url))
        
        # Eseguiamo tutto insieme!
        risposte = await asyncio.gather(*tasks)
        return risposte

*Invece di aspettare 1 secondo per ogni richiesta (10s totali), le eseguiamo in parallelo logico finendo in poco più di 1 secondo.*

Robustezza: Errori e Timeout

Nelle API asincrone, è facile che qualcosa fallisca. Dobbiamo gestire i timeout per evitare attese infinite. 

from asyncio import TimeoutError

async def chiamata_sicura(session, url):
    try:
        # Se l'API non risponde entro 5 secondi, interrompi
        async with asyncio.timeout(5):
            async with session.get(url) as resp:
                return await resp.json()
    except TimeoutError:
        print(f"Errore: L'API su {url} è troppo lenta!")
    except Exception as e:
        print(f"Errore generico: {e}")

Quando usare (e NON usare) Async

Usa Async se:

  • Fai molte chiamate API (SharePoint, OpenAI, Auditio).
  • Scandagli migliaia di file su un server remoto.
  • Vuoi un'interfaccia utente che non si blocchi mentre elabori.

NON usare Async se:

  • Fai calcoli matematici pesanti (usa il Multiprocessing).
  • Devi processare un'immagine enorme con OpenCV (operazione CPU-bound).
  • Il tuo script è molto semplice e fa una sola operazione alla volta.

Dall'OCR all'Informazione

L'OCR (Tesseract/EasyOCR) ci dà del testo, ma spesso:

  • L'ordine delle colonne è saltato (nelle tabelle).
  • Ci sono errori di battitura (es. "I" invece di "1").
  • Il testo è "sporco" di metadati inutili.

L'AI (LLM via API) agisce come un correttore semantico: non legge solo i caratteri, capisce che "IVA 22" è un'aliquota e non un numero civico.

Prompt Engineering Tecnico: I 3 Pilastri

Per ottenere output affidabili non basta "chiedere". Serve una struttura:

  1. Ruolo: "Sei un esperto di data extraction specializzato in fatture storiche."
  2. Task: "Estrai i dati dal testo OCR fornito. Se un dato è incerto, usa null."
  3. Schema: Definire esattamente i campi (es. P.IVA, Data, Totale).

Trucco: Fornire un esempio di "One-Shot" (un esempio di input e l'output desiderato) aumenta la precisione del 30%.

Obbligare l'AI alla Struttura (JSON Mode)

Non vogliamo "chiacchiere" dall'AI (es. "Ecco i dati richiesti..."). Vogliamo solo un JSON puro.
Utilizzeremo il JSON Mode delle API (OpenAI/Anthropic):

  • Si imposta nel parametro della chiamata: response_format={"type": "json_object"}.
  • Nel prompt si deve includere esplicitamente la parola "JSON".

IA e JSON

Robustezza: Gestione Errori e Retry

Le chiamate API possono fallire per:

  • Connessione internet assente.
  • Rate Limiting (hai fatto troppe richieste in un minuto).
  • Timeout del server.

Non useremo semplici cicli while. Useremo la libreria Tenacity per gestire il Retry con Exponential Backoff (aspettare sempre un po' di più tra un tentativo e l'altro).

Strategie per Documenti Complessi

  • Checklist: Chiedi all'AI di interpretare le crocette: "Se vedi un carattere [X] o [V] vicino a 'Conforme', imposta conforme=true".
  • DDT/Fatture: Chiedi di sommare le righe per verificare che il totale estratto sia corretto (Self-Verification).
  • Documenti Storici: Fornisci all'AI una "lista di nomi noti" (Context Injection) per aiutarla a correggere nomi di città o cognomi parzialmente illeggibili.

Logica di Fallback (Motori Combinati)

Nessun OCR è perfetto al 100%. In produzione si usa una logica di Fallback:

  1. Prova con Tesseract (veloce).
  2. Se il risultato non passa una validazione (es. manca il numero di fattura) o la confidenza è < 50%.
  3. Prova con EasyOCR (più potente ma lento).
  4. Prova con AI
  5. Se fallisce ancora, segnala l'errore per intervento umano.
